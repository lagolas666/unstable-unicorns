## 3. Дефекты, сгруппированные по корневой причине

### DEF-01 — Оплата стоимости (discard / sacrifice) не применяется в `playWithTargets`
Покрывает падения №2, №4, №7, №9, №10 (5 из 10).

**Баг:** при розыгрыше карты с выбором целей выбранные карты стоимости не уходят в сброс / не жертвуются, эффект карты при этом не наступает.
**Шаги воспроизведения:**
1. Игрок A с рукой `[h1, h2, h3]`, у него активен Gemini Unicorn.
2. Сыграть Gemini Unicorn с выбором «discard h1».
3. Проверить `players.A.discard` и `action_points`.
**Ожидаемое поведение:** `discard == ["h1"]`, `hand == ["h2","h3"]`, `action_points == 2`.
**Фактическое поведение:** `discard == []` — карта стоимости не перемещена; далее по цепочке `action_points` не растёт, steal не срабатывает.
**Серьёзность:** Critical
**Влияние:** ломает всю группу карт со стоимостью discard/sacrifice (в тестах — минимум Rainbow Lasso, Gemini Unicorn, Nightmare Unicorn; по правилам это обширный класс Magical/Magic-карт). Это блокер релиза: игрок платит стоимость, но эффекта нет — «карта в никуда».
**Логи:** `test/rainbow_lasso.test.ts:51`, `test/gemini_unicorn.test.ts:42`, `test/reactions.test.ts:971` (`Expected "S1", received []`).

### DEF-02 — Реакция `redirect` не принимается сервером
Покрывает падения №5, №6, №3.

**Баг:** redirect-реакция (перенос цели уничтожения) отклоняется или не применяется при разрешении.
**Шаги воспроизведения:**
1. Игрок A играет destroy по цели X у игрока B.
2. Игрок C (или B) играет redirect в окно реакции, указывая цель Y.
3. Сервер разрешает стек.
**Ожидаемое поведение:** HTTP 200, эффект применяется к Y, X остаётся жив; в окне `trigger_effect` статус сохраняется.
**Фактическое поведение:** в `reactions.prevent-ignore.test.ts:127` — `Expected 200, Received 400`; в `reactions.test.ts` цель не меняется; в `reaction_triggers` redirect не проходит при uncounterable destroy.
**Серьёзность:** Critical
**Влияние:** механика реакций (Neigh/Nope, redirect, intercept) — ядро игры по правилам. 400 на легальное действие означает, что клиент не сможет показать валидную опцию, а игрок потеряет карту без эффекта. Плюс расхождение контракта: `400` возвращается и там, где он ожидаем, и там, где нет (см. №8).

### DEF-03 — Триггер `when_destroyed` не даёт владельцу взять карту
Падение №1.

**Баг:** при уничтожении единорога владелец не берёт 1 карту из общей колоды.
**Шаги воспроизведения:**
1. У игрока A на stable стоит единорог с `when_destroyed`.
2. Соперник применяет destroy к этому единорогу.
3. Проверить руку A и размер общей колоды.
**Ожидаемое поведение:** `hand` A +1, общая колода −1.
**Фактическое поведение:** рука не меняется, триггер не срабатывает.
**Серьёзность:** High
**Влияние:** обнуляет защитную ценность целого класса карт; игрок принимает решения на основе неверной информации.

### DEF-04 — Код ответа `400` на неплатёжеспособность не соответствует контракту
Падение №8.

**Баг:** негативный кейс «не хватает карт для оплаты discard» не отдаёт ожидаемый ответ.
**Шаги воспроизведения:** игрок с 1 картой в руке пытается оплатить discard 3.
**Ожидаемое поведение:** отказ с 400, состояние игры не меняется.
**Фактическое поведение:** ответ не совпадает с ожидаемым — тест красный.
**Серьёзность:** Medium
**Замечание:** связан с DEF-01 (та же ветка оплаты стоимости), вероятно закроется тем же фиксом. Тестировать после DEF-01.
