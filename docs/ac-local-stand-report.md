# Локальный стенд: что работает, что нет (отчёт Аналитика, 30.10.2026)

Стенд поднят на этой машине: MongoDB 27017, API 3001, клиент 5173.
Проверки шли через REST/API-скрипты, не через браузер.

## Как посмотреть

- Клиент: http://localhost:5173/ — страницы `/`, `/cards`, `/admin`, `/playtest`, `/lobby`, `/room/:roomId`
- API: http://localhost:3001/api/health → `{"ok":true}`
- Каталог карт: http://localhost:3001/api/cards?limit=100

Смотреть игру нужно на `/playtest` — это единственная страница, которая ходит в полный движок.
`/lobby` и `/room` — скелет, розыгрыша карт там нет.

## Что сломано (главное)

**1. Магия не делает ничего.** У 583 карт поле `effects` заполнено только у 27 (и это демо-карты «QA: …»),
у остальных 556 — пустой массив. Движок эффекты берёт строго из `card.effects`
(`routes/game.ts` L213, L262, L383, L484, L650, L723, L813; `executor.ts` L307-315), поэтому
любая Magic/Upgrade/Downgrade без `effects` разыгрывается «в пустоту».

**2. Окно Ржания не открывается.** В `gameService.ts` окно реакции создаётся только если
`hasDangerousEffect(card) || hasUnicornOnPlayEffect(card)` (L583) — обе функции читают `card.effects`.
`effects` пуст → `pending = null`, Ржание невозможно, отменить чужой розыгрыш нельзя.
Проверено на 25 играх подряд: карты с непустыми effects в руку не попадали, окно ни разу не открылось.

Причина в источнике данных: загрузчик кладёт тексты описаний, но не структурные эффекты.
Восстановить эффекты можно только из текста (стрип повреждённого текста в `unicorns.json`),
это отдельная работа, не правка одной строки.

## Что мешает проверке глазами

- `POST /:id/play` возвращает только `state`, без `pending` (`routes/game.ts` L~40 блока play),
  поэтому клиент не узнаёт про открытое окно реакции из ответа — ждёт `pending_update` по сокету.
- `/api/cards` отдаёт максимум 100 за страницу (limit 50 по умолчанию) — «total 50» на `/admin`
  это лимит страницы, а не число карт.
