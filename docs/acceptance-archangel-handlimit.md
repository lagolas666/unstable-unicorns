## Кейс 1 — окно замены Архангела (`archangelWindow.test.ts`)

Правило UNICORNS.md п.78: уничтожение/жертвоприношение карты в стойле владелец может
заменить сбросом карты из руки. Решается игроком, а не кодом.

- **W1** — владелец выбрал `H_keep`: карта ушла в сброс, Архангел остался в стойле, рука `['H_two']`.
  Окно проверено по полям: `kind='await_choice'`, `purpose='archangel_prevent'`,
  `chooserId='P1'`, `actorId='P2'`, `sourceCardId`, `options`, `deferred={zone:'stable',cardId:ARCH,kind:'destroy'}`.
  До ответа стойло не мутирует — это и отличает выбор от автоматики.
- **W2** — отказ (`{decline:true}`): Архангел уничтожен и в сбросе, рука не тронута.
- **W3** — карта не из руки (`H_two` при руке `['H_keep']`): 400, состояние побайтово
  идентично (сравнение `JSON.stringify`), окно живо.
- **W4** — пустая рука: платить нечем, окно `archangel_prevent` не открывается, уничтожение сразу.
- **W5** — контроль: без Архангела в стойле окна нет, цель уходит в сброс.

## Кейс 2 — таймаут окна Архангела (`archangelTimeout.test.ts`)

Окон **два подряд**: 5 с окно реакции на розыгрыш (`kind='play'`), затем 5 с окна замены.
Отсюда `jest.setTimeout(40000)` и ожидание ≥10 с — иначе тест ловил бы живое окно, а не таймаут.

- **T1** — владелец не ответил: окно закрылось само, Архангел в сбросе, рука `['H_keep']` цела.
  Таймаут = отказ: карту за игрока не сбрасывают.
- **T2** — уничтожение не дублируется: `discard.filter(ARCH).length === 1`, стойло `['U_spare']`.

## Кейс 3 — лимит руки BUG-01 (`handLimitTurnTimer.test.ts`)

- **R1** — транспорт: `POST /api/game/:id/endTurn` при руке 8/7 отдаёт **200** и окно
  `hand_limit` прямо в теле (`pending.kind/purpose/chooserId/remaining/options` + `state`).
  Без этого клиент не узнаёт, что от него ждут выбора.
- **R2** — таймер (ждём 7 с при сроке окна 5 с, дедлайн проверяется явно): карта за игрока
  **не** сбрасывается, ход у `p1`, рука 8, сброс пуст, окно живо.
- **R3** — повторный `endTurn` не дублирует эффекты конца хода (счётчик `type==='end'` в логах
  не растёт) и отдаёт то же окно с `remaining=1`.
- **R4** — выбор игрока закрывает окно: рука 7, карта в сбросе, ход у `p2`.

## Замечания для Бэкенда

1. В `server/src/routes/game.ts` L635 `GET /api/game/test/state/:id` **отдаёт** `pending`, но хелпер
   `getState` в `server/test/helpers/api.ts` возвращает только `res.body.state` — окно теряется.
   В новых сьютах `pending` читается из `games.get(id).pending`. Хелпер стоит доработать.
2. `Jest did not exit one second after the test run has completed` на первом прогоне
   `archangelWindow` — держит таймер окна; в гейте `--forceExit`-подобного предупреждения нет,
   на результат не влияет.
3. Наблюдение Бэкенда (не дефект): `endTurn` — единственный роут без обязательного `playerId`,
   поэтому окно `hand_limit` открывается без проверки актора. Это вне рамок трёх кейсов.
