## Найденный дефект: окно не доезжает до клиента через REST `/endTurn`

**Баг:** `POST /api/game/:id/endTurn` не возвращает открытое окно выбора в теле ответа.
**Шаги:**
1. Собрать состояние, где у текущего игрока 8 карт (лимит 7).
2. `POST /api/game/:id/endTurn`.
**Ожидаемое:** тело ответа содержит `pending` (`kind`, `purpose`, `chooserId`, `expiresAt`), как у соседнего роута на `server/src/routes/game.ts` L914: `res.json({ pending, state })`.
**Фактическое:** `server/src/routes/game.ts` L927-933 отдаёт только `state`; при этом L930 broadcast'ит `state_update` вместо `pending_update`. Окно видно только через `GET /api/game/test/state/:id`, то есть коммерческому клиенту недоступно.
**Серьёзность:** High — игрок с 8 картами не узнаёт, что от него ждут выбора; интерфейс зависает в ожидании.
**Тест-страж:** `e2eSixPlayers.test.ts` A3, строка `expect(res.body.pending).toBeUndefined()` фиксирует текущее поведение. После фикса ожидание переворачивается на `toBeTruthy()`.

## Остаток гейта: 2 красных теста в read-only файлах

Полный гейт: 45 сьютов / 458 тестов / **453 passed / 2 failed / 3 skipped**, `TSC_EXIT=0`,
`src/gameService.ts` sha до и после прогона идентичен (`1b0fae26…`).

1. **`playContract.test.ts` E3** (строки 267-281) ждёт `400 "Hand limit exceeded: 8/7"` и «ход не передан». Рулинг BUG-01 отменяет этот ответ: рука 8 карт больше не отказ, а окно выбора. Ожидание устарело.
2. **`socket.test.ts` S20** (строки 492-506) ждёт, что отменённая Neigh карта остаётся **в руке** актёра (`p1.hand` содержит `c_basic_1`). Это ровно BUG-02, рулинг прямо называет текущее поведение ошибочным: карта должна уходить в **сброс**, а не в руку. Ожидание противоречит рулингу.

Оба файла помечены как read-only для Тестировщика — жду решения Аналитика: переписать ожидания или оставить как фиксацию дефектов.
