## 3. Новая находка N-1 (не входила в задачу, тот же класс дефекта)

`swapOpponentCandidates` L673-676: когда транспорт передал явный выбор
(`ctx.selectedPlayers[sourceId]`), соперник возвращается **до** `swapEligibleOwners`,
то есть без `isTargetableFor`.

Пробник `_an_swapsync3_probe2.js` (текущий код, sha `aa7e74ce9d6d857f`):

| Кейс | OK | QTY | ASYMMETRY |
|---|---|---|---|
| B1 2 игрока, явно выбран защищённый p2 | false | 1 | **true** |
| B2 3 игрока, явно выбран защищённый p2 (p3 свободен) | false | 1 | **true** |
| B3 3 игрока, явно выбран свободный p2 | true | 1 | false |
| B4 2 игрока, явно выбран свободный p2 | true | 1 | false |

Механика: `isActionPossible` L477 → `swapOpponentCandidates` → явный выбор отдаётся как есть →
`countTargetsForOwners` фильтр `matchesFilter` проходит (флаг не в фильтре) → предпроверка `true`.
`collectSide` L1399 дополнительно зовёт `isTargetableFor` → исполнение `false`.
**Класс #35: предпроверка «можно», исполнение отказывает.**

Насколько это наблюдаемо через транспорт: `swapChoiceRequirement` → `swapCandidatesFor` фильтрует
через `swapEligibleOwners` с actorId, поэтому защищённый в `candidates` не попадает, L737 отклонит
`targetPlayerId` с 400. **Через /play дыра прикрыта**, но:
- на v2 носителей признака 0 карт (`cannot_be_targeted` 0, масок 0) — на данных не наблюдается ни там, ни там;
- для эффектов внутри `resolveEffect` (swap как действие карты, не как розыгрыш) путь `selectedPlayers`
  заполняется L177-183/219-225/792 и идёт мимо `swapChoiceRequirement` — там рассинхрон живой.
