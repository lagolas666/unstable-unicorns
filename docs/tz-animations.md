| Проверка | Результат |

| Отрисованы ли стойла в GameRoom | **нет**. `pages/GameRoom.tsx` показывает список игроков текстом, руку кнопками и лог. Стола со стойлами нет |

## 1. Два вывода, которые меняют порядок работ

**1.1. Журнал не годится как источник анимаций.** Сервер не пишет `destroy`/`steal`/`discard`/`move` — из 42 записей журнала 37 это `react` и `debug`. Если строить анимации на `logs_update`, события «уничтожение», «кража», «сброс» не будут замечены вообще.
Решение: единственный источник — **дифф двух подряд идущих `state_update`** по `players[].stable`, `players[].hand`, `state.discard`. Сервер для этого менять не нужно. Журнал остаётся для подписи в оверлее («кто что сделал»), но не как триггер.

**1.2. Пока в GameRoom нет стойл, анимировать «карта летит в стойло» не на что.** 6 из 12 событий таблицы («розыгрыш в стойло», «кража», «штрафное животное», «уничтожение») требуют видимого стола. Значит порядок такой: сначала верстка стола (стойла всех игроков, рука, сброс, колода), потом анимации на нём.

## 2. Порядок внедрения (по документу, с поправкой)

### Шаг 0. Стол (предусловие, отдельная задача)
- `components/table/StableZone.tsx` — стойло игрока, карты из `p.stable` через `CardView`.
- `components/table/HandZone.tsx` — своя рука, карты, а не кнопки.
- `components/table/PileZone.tsx` — колода и сброс со счётчиками.
- Каждая карта получает стабильный `data-card-id` и реф — из него берём координаты для перелёта.

### Шаг 1. Framer Motion: пункты 1, 3, 7
Без звука и частиц.
1. **Наведение на карту** — `whileHover={{ y: -8, scale: 1.05, rotate: -1 }}`, тень; в `CardView` заменить CSS-`transition` на `motion.div`.
3. **Розыгрыш карты** — общая летящая карта: до клика запоминаем `getBoundingClientRect()` источника, после `state_update` находим карту в новом месте и анимируем через `layoutId={cardId}` + `AnimatePresence`. `layoutId` покрывает и руку→стойло, и стойло→сброс.
7. **Нажатие на кнопку** — `whileTap={{ scale: 0.96 }}` в `StoneButton`, единая точка.

Приёмка шага: перелёт виден при розыгрыше из руки в своё стойло и при сбросе; карта не «прыгает» при перерисовке; `prefers-reduced-motion` отключает перелёт (остаётся мгновенное появление).

### Шаг 2. tsparticles: пункты 4 и 3
- **Магические карты** (`type === 'magic'`): искры 400–600 мс в точке приземления.
- **Обычные карты**: пыль, короткий `burst` 30–40 частиц.
- Частицы ставим **под** картами (`z-index`), чтобы не перекрывать текст.
- Один `ParticlesProvider` на комнату, а не инстанс на карту: 7 стойл × N карт иначе дают N canvas.
Приёмка: два розыгрыша подряд дают два отдельных всплеска, canvas не растёт в числе.

### Шаг 3. Howler: звуки
**Блокер по контенту: аудиофайлов в проекте нет.** Нужны минимум 6: upgrade, downgrade, spell, neigh, draw, win. До получения файлов делать не начинаем — пустой `howler` без ассетов ничего не проверяет.
Когда файлы есть: `client/src/audio/soundManager.ts` — ленивая загрузка, `mute` в localStorage (`uu_sound_muted`), кнопка mute в GameRoom, `Howler.autoUnlock` для политики автоплея браузера.

## 3. Сопоставление 12 событий с реализуемостью

| Событие | Триггер на клиенте (дифф) | Что рисуем | Тип карты | Статус |
|---|---|---|---|---|
| Upgrade | `upgrade` появился в `stable` | оранжевая стрелка вверх, золотое свечение | `upgrade` | шаг 1+2 |
| Downgrade | `downgrade` появился в `stable` | жёлтая стрелка вниз, тёмный дым | `downgrade` | шаг 1+2 |
| Spell | `magic` пришёл в `stable`, затем ушёл в `discard` | подъём в центр, зелёные/синие частицы, улёт в сброс | `magic` | шаг 1+2, нужен контроль задержки |
| Instant/Neigh | `kind` из `pending` (`prevent`, `cancel`, `rewind`) | стоп-кадр, печать «ОТМЕНЕНО», скрещённые мечи | `instant` | шаг 1, данные уже есть в `game.pending` |
| Skip Phase | `phase` сменилась без действия игрока | перечёркнутая подпись фазы, гаснет | — | шаг 1. Отличить «пропуск» от «перехода» сложно: предлагаю считать сигналом смену `has_drawn` без `draw` в логе |
| Non-Unicorn (штрафное) | карта не-единорог появилась в `stable` | «шлёпок» + пыль, серая рамка, значок «не в счёт» | любой не `*unicorn` | шаг 1+2 |
| Draw | выросла `me.hand`, у соперника выросла `hand.length` | карта рубашкой из колоды, свуш | — | шаг 1. У соперника рука скрыта — анимируем только счётчик |
| Discard | `hand.length` упала до 7 при `discard` рост | пепел/осколки в стопку сброса | — | шаг 1+2 |
| Destroy | карта исчезла и **не** появилась в `discard` получателя | тряска, взрыв, обломки | — | шаг 1+2. Отличить от сброса можно только по отсутствию в `discard` |
| Steal/Swap | карта ушла из `stable` A и появилась в `stable` B | дуга между стойлами, стрелки/рука | — | шаг 1. **Работает и для не-единорогов** — запрет красть котов это правило движка, не UI |
| End Turn | сменился `turn.currentPlayerId` | волна по экрану, пульсация аватара | — | шаг 1 |
| Победа | `state.winnerId` перешёл из пустого в значение | 7 единорогов по радуге или корона, конфетти | — | шаг 1+2 |

Замечание по таблице из документа: в строке «Кража/Обмен» стоит проверка «нельзя красть котов/панд (не-единорогов)». Этой проверки на клиенте быть не должно — решение принимает сервер, клиент только рисует результат. Иначе получим вторую копию правил и расхождение с движком.

## 4. Технические ограничения

- **Не дублировать правила.** Клиент ничего не решает: `canReact`, запреты, лимиты — только сервер (уже принято 28.10.2026).
- **`prefers-reduced-motion`** — обязательный выключатель перелётов и частиц, звук отдельно.
- **Производительность**: 7 игроков, до 7+ карт в стойле у каждого. Анимации не должны держать ре-рендер всего стола — мемоизировать `StableZone`.
- **Первое монтирование**: после `join_game` диффа нет, всё появившееся **не** анимируем (иначе при входе в комнату весь стол «прилетает» разом).
- **Реконнект**: `state_update` после переподключения тоже не должен давать каскад анимаций — сбрасывать базу диффа.

## 5. Что не входит

- Макеты: редизайн GameRoom ждёт фреймы от Даниила. Анимации делаем на текущей вёрстке стола, после её появления.
- Звуковые ассеты — ждут контента.
- Смена фаз на сервере, новые поля в `state_update` — не нужны, диффа достаточно.

## 6. Порядок приёмки

1. Шаг 0 (стол) — `tsc --noEmit` и `vite build` оба exit 0, стойла видны у всех игроков.
2. Шаг 1 — наведение, перелёт, нажатие; проверка на 7 игроках, `reduced-motion`.
3. Шаг 2 — частицы по типу карты.
4. Шаг 3 — после получения аудиофайлов.
