# BUG-SWAP-03: сторона B обмена — ровно один соперник

Дата: 07.11.2026. Автор: Единорог Бэкенд. Файл правки: `server/src/engine/executor.ts`.
Бэкап базы: `server/src/engine/executor.ts.prev_swap3` (sha `e7c01fb3d404f65e…` — ровно та версия, что пришла в вердикте).

## Причина (подтверждена кодом и данными)

`dirty_deal_spell` (единственная карта с `swap` в каталоге v2):
`target.scope='self'`, `target.quantity.value=99`, `destination_player='chosen'`, `destination='hand'`.

1. `actionDestination` L518 схлопывал `'chosen'` в `scope='any_player'` — признак «игрок выбирается явно» терялся.
2. `swapSideOwners(ctx, player, bSel, true)` для широкого scope возвращал **всех** игроков, а `filter(o => o.id !== player.id)` оставлял **всех соперников** — это верно для 2 игроков и неверно для 3+.
3. `collectSide` собирал по карте с каждого соперника, `takeOut` возвращал отдельный слот на каждую руку, а вкладывание шло одним и тем же `aIds` в **каждый** слот (`for (const s of slotB) s.arr.splice(s.index, 0, ...aIds)`) — карты актора клонировались.

## Воспроизведение (пробник `_be_swap3_probe.js`, реальные карты catalog.v2.json)

До фикса, `ok=true` при сломанном инварианте:

| конфигурация | было | результат |
|---|---|---|
| 3 игрока 1:1:1 | 3 карты | 3 → **4**, дубль `apprentice_unicorn` |
| 4 игрока 2:2:2:2 | 8 карт | 8 → **12**, 3 дубля |
| 6 игроков 1:1:1:1:1:1 | 6 карт | 6 → **9**, дубль |

2 игрока — инвариант цел: кандидат ровно один, поэтому S1–S5 оставались зелёными.

## Фикс (3 точечные правки, каждая hits=1)

1. **Новый хелпер `swapOpponentCandidates(ctx, owners, selector)`** перед `countTargetsForOwners`:
   - `owners.length <= 1` → как есть;
   - есть `ctx.selectedPlayers[sourceId]` → ровно этот игрок (канал уже работает в `executePull`, L745, и его заполняет транспорт в `routes/game.ts:783`);
   - явного выбора нет → единственный соперник с подходящей картой; несколько → `undefined` (отказ, окно выбора открывает транспорт); ни одного → `[]`.
2. **`isActionPossible` (ветвь swap)** — `bResolved` отсекает неоднозначность до исполнения, иначе UI считает карту играбельной при честном `false` в исполнении.
3. **`executeAction` (ветвь swap)** — `bOwners = resolvedB`, сторона B ровно один соперник.

## Что Тестировщику (Не делал — его зона)

1. Инвариант «сумма карт в руках до == после, дублей нет» на 3/4/6 игроках в `server/test/` — включая **отказ** при `ok=false`.
2. Обязательное правило фикстур: id карт уникальны по игрокам, иначе счётчики дают ложное «OK».
3. Кейс на журнал: при неоднозначном автоподборе событие `action_resolved` с `success=false` должно быть **одно** (из предпроверки), а не из обеих точек.
4. S1–S5 не трогал; расхождений не зафиксировано.

## Открытое (решение Аналитика)

- `swapSideOwners` фильтрует актора и для `all_players` — для swap семантика «со всеми» не нужна, но правило единое. Если понадобится обмен «со всеми», это новый kind, а не побочный режим swap.
- Транспорт при `'chosen'` и 3+ игроках обязан открывать окно выбора, иначе карта не сыграется (`isActionPossible` вернёт false). Проверить `routes/game.ts` — зона Аналитика.
